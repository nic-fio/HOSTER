Usare hoster

Come installare hoster, preparare account e link, scaricare, estrarre gli archivi e cavarsela quando qualcosa non va. Alla fine trovi il riferimento completo di tutte le opzioni.

Versione 1.0 Sistema Linux (x86-64 e ARM a 64 bit) Siti famiglia XFileSharing

Sommario

Premi / per cercare. L'indice analitico in fondo elenca opzioni, file e argomenti.

Introduzione

Che cos'è hoster, cosa fa e cosa volutamente non fa.

Che cos'è

hoster è un programma da terminale per scaricare file dai siti di file hosting (terabytez, filestore, worldbytez e simili) usando i tuoi account. Fa quello che faresti a mano nel browser — entrare con utente e password, aprire ogni link, premere «scarica» — ma per tutti i link insieme, senza toccare niente. È pensato come JDownloader, ma senza Java: è un unico file eseguibile e non ha bisogno di installare altro.

1

Scrivi gli account in account e i link in links, poi lanci ./hoster.

Apre gli archivi RAR (anche in più parti e con password) e ZIP, senza programmi aggiuntivi.

Nome giusto

Anche quando il sito mostra solo un codice, il file viene salvato con il suo vero nome.

?

Guida integrata

hoster --help apre una guida a schede nel terminale.

Cosa non fa

hoster usa soltanto il percorso «premium»: quello che il sito offre a chi ha un account a pagamento e fa il login. Non aggira captcha, attese o limiti dei siti gratuiti. Se un sito chiede di aspettare un conto alla rovescia, hoster si ferma e ti dice che l'account non risulta premium.

Uso previsto

Scaricare con i propri account contenuti che si è autorizzati a scaricare — per esempio le immagini di una distribuzione Linux — come si farebbe con JDownloader.

Come funziona, in breve

flowchart LR
  A["account + links"] --> B["login una volta<br/>per ogni sito"]
  B --> C["link diretto<br/>di ogni file"]
  C --> D["download in parallelo<br/>con ripresa"]
  D --> E["estrazione<br/>(se chiesta con -e)"]

I link diretti dei siti scadono in fretta, perciò hoster lavora a gruppi: prende 5 link (o quanti ne indichi con -j), ricava i loro link diretti, li scarica insieme e solo dopo passa ai 5 successivi.

Installazione

Due strade: scaricare il programma pronto, oppure costruirlo dal codice sorgente.

Il programma pronto

Nella pagina delle release su GitHub ci sono due file:

FilePer
hoster-linux-amd64PC e tablet con processore Intel o AMD (la maggior parte).
hoster-linux-arm64Dispositivi ARM a 64 bit, per esempio un Raspberry Pi 4 o 5.

Se non sai quale ti serve, il comando uname -m te lo dice: x86_64 vuol dire amd64, aarch64 vuol dire arm64. Scaricato il file, crea una cartella di lavoro e mettilo lì:

$ mkdir ~/hoster && cd ~/hoster
$ mv ~/Scaricati/hoster-linux-amd64 hoster
$ chmod +x hoster
$ ./hoster --help

Dal codice sorgente

Serve una macchina Debian o Ubuntu con connessione a Internet. Lo script tools/setup-dev.sh controlla e installa quello che manca (il compilatore Go e pochi altri pacchetti; chiede la password per sudo):

$ git clone https://github.com/nic-fio/HOSTER.git
$ cd HOSTER
$ tools/setup-dev.sh --install
$ make
$ make test

make crea il programma in build/hoster; make test esegue tutti i controlli automatici. Il programma costruito così è identico a quello delle release.

Dove cerca i suoi file

hoster cerca account, links e passwords.txt nella cartella da cui lo lanci (non in quella dove si trova il programma), e salva i download in downloads/ dentro la stessa cartella. Il modo più semplice è tenere tutto insieme in una cartella e lanciare ./hoster da lì. Con le opzioni -a, -i e -d puoi indicare file e cartelle diversi.

Primi passi

Preparare i due file, controllare che tutto sia a posto e fare il primo download.

Il file account

Una riga per ogni sito, con dominio, utente e password separati da due punti:

# Le righe che iniziano con # sono commenti.
terabytez.org:mariorossi:la-mia-password
filestore.me:mrossi;altra:password;con:simboli
  • Al posto dei due punti : va bene anche il punto e virgola ;, anche mescolati.
  • Solo i primi due separatori contano: la password è tutto il resto della riga, quindi può contenere :, ; e qualunque altro carattere.
  • Non mettere spazi attorno ai separatori: uno spazio dopo il secondo separatore diventerebbe parte della password.
  • Il dominio si può scrivere anche senza la parte finale: terabytez:utente:password vale sia per terabytez.org sia per terabytez.com. Si può scrivere anche www. davanti o l'indirizzo completo con https://: vengono ignorati.

Nel repository c'è un modello, account.example: copialo in account e sostituisci i dati.

Attenzione

Il file account contiene le tue password in chiaro. Non condividerlo e non caricarlo su GitHub: il repository di hoster è configurato per ignorarlo (.gitignore), ma una copia messa altrove non è protetta. Conviene rendere il file leggibile solo a te: chmod 600 account.

Il file links

Un link per riga, così come lo copi dal browser. Le righe vuote e quelle che iniziano con # vengono saltate, e se lo stesso link compare due volte viene scaricato una volta sola.

# Kali, set completo
https://terabytez.org/abc123def456/kali-linux.part01.rar
https://terabytez.org/ghi789jkl012/kali-linux.part02.rar
https://filestore.me/nhail4vmw015

I link possono essere di siti diversi, mescolati: hoster fa il login su ognuno la prima volta che gli serve.

Prova senza scaricare

Prima di un download lungo conviene controllare che login e link funzionino. Con --dry-run hoster entra nei siti, ricava i link diretti e li mostra, senza scaricare niente:

$ ./hoster --dry-run
✓ kali-linux.part01.rar
  https://terabytez.org/abc123def456/kali-linux.part01.rar
✓ debian-12.iso
  https://filestore.me/nhail4vmw015

risolti: 2  falliti: 0

Ogni riga con ✓ è un file pronto da scaricare, con il suo nome vero e l'indirizzo da cui partirà (con gli account premium spesso coincide con il link originale, perché il sito manda direttamente il file). Una riga con ✗ dice cosa non va: il capitolo Problemi e soluzioni spiega ogni messaggio.

Ogni file in corso ha la sua riga: nome, barra, percentuale, quanto è stato scaricato sul totale, velocità e tempo che manca. Quando un file finisce, la sua barra diventa una riga con ✓ e la dimensione. L'ultima riga conta i file in corso, quelli finiti e, se ce ne sono, quelli falliti. Alla fine compare il riepilogo:

I file sono in downloads/. Mentre un file è in corso si chiama NOME.part; prende il nome definitivo solo quando è completo e controllato.

Suggerimento

Per scaricare ed estrarre in un colpo solo: ./hoster -e -p LAPASSWORD. Vedi Estrarre gli archivi.

Scaricare

Come si comporta hoster durante il download e come regolarlo.

Quanti file insieme

Di norma hoster scarica 5 file alla volta. Con -j scegli un numero diverso: -j 2 per una connessione lenta o per un sito che non ama troppi download contemporanei, -j 10 se la linea regge. Lo stesso numero decide anche la grandezza dei gruppi: hoster ricava i link diretti di un gruppo, lo scarica tutto e passa al gruppo successivo solo quando l'ultimo file del gruppo è finito.

Connessioni per file

Ogni file viene scaricato con una sola connessione, che è quello che gli account premium concedono di solito. Se un sito permette più connessioni sullo stesso file, -s 4 divide ogni file in 4 pezzi scaricati insieme. Vale solo per file da almeno 1 MB e solo se il sito accetta download «a pezzi»; altrimenti hoster usa comunque una connessione.

Interruzioni e ripresa

Se la connessione cade durante un file, hoster riprova da solo fino a 5 volte (opzione --retries), aspettando 2 secondi tra un tentativo e l'altro (--retry-wait), e riparte dal punto a cui era arrivato, senza ricominciare da capo quando il sito lo permette.

Se invece interrompi tu il programma (Ctrl+C), o si spegne il computer, rilancialo con -c:

$ ./hoster -c

I file rimasti a metà (.part) ripartono da dove erano arrivati.

Da sapere

Senza -c, i file già completi in downloads/ vengono saltati e quelli a metà ricominciano da zero. Con -c, invece, anche i file già completi vengono scaricati di nuovo. Se nella lista ci sono file già finiti, conviene toglierli da links (o commentarli con #) prima di rilanciare con -c.

Link scaduti

Un link diretto vale per poco tempo. Se scade mentre il file è in coda o a metà, il sito risponde con un rifiuto; hoster se ne accorge, torna alla pagina originale del file, ricava un link nuovo e continua. Lo fa fino a 2 volte per file e lo segnala con una riga:

nota: link diretto scaduto, lo rigenero (kali-linux.part07.rar)

Nomi dei file e doppioni

Alcuni siti mettono il nome del file nel link (…/kali-linux.part01.rar), altri solo un codice (https://filestore.me/nhail4vmw015). hoster cerca il nome vero nella pagina del file, nel link diretto e infine in quello che dichiara il server all'inizio del download, e salva sempre con il nome vero.

Se due link portano allo stesso file (per esempio lo stesso archivio su due siti diversi), il secondo viene saltato con la riga • nome (duplicato, ignorato).

Limitare la banda

--rate fissa un limite complessivo, valido per tutti i download insieme:

$ ./hoster --rate 2M

Le unità sono k, M, G (anche minuscole) e valgono byte al secondo: 2M è circa 2 megabyte al secondo, cioè circa 16 megabit. Sono ammessi i decimali: 1.5M. 0, il valore normale, vuol dire nessun limite.

Reti lente o instabili

--timeout (60 secondi) è il tempo massimo di attesa perché un server risponda all'inizio di un download. Non limita la durata del download: un file di molti gigabyte può durare quanto serve. Su una rete molto lenta si può alzare, per esempio --timeout 120, insieme a --retries 10.

Un'altra cartella o un'altra lista

$ ./hoster -i kali.txt -d /media/disco/iso

Usa la lista kali.txt al posto di links e salva in /media/disco/iso (creata se non c'è).

Estrarre gli archivi

Aprire gli archivi RAR e ZIP scaricati, anche divisi in più parti e protetti da password.

Scaricare ed estrarre

$ ./hoster -e -p LAPASSWORD

Con -e, finiti i download, hoster estrae tutti gli archivi che trova nella cartella dei download, nella stessa cartella:

== estrazione ==
• kali-linux.part01.rar
  ✓ estratto (integrato, password trovata)

Estrarre una cartella già scaricata

$ ./hoster --extract-only downloads -p LAPASSWORD

Non scarica niente e non ha bisogno di account né di links: estrae gli archivi di downloads ed esce.

Archivi in più parti

Un archivio grande è spesso diviso in parti: nome.part01.rar, nome.part02.rar… hoster riconosce il gruppo e lo estrae una volta sola, partendo dalla prima parte. Servono tutte le parti nella stessa cartella: se ne manca una, l'estrazione di quel gruppo fallisce (le altre proseguono).

Password

Per ogni archivio hoster prova, in quest'ordine:

  1. Nessuna password (molti archivi non ne hanno).
  2. La password data con -p, se c'è.
  3. Le password del file passwords.txt, una per riga, dall'alto in basso (le righe vuote e quelle con # vengono saltate). Il file è facoltativo; --pwfile ne indica un altro.

Il messaggio finale dice se è servita una password (password trovata) ma non quale, perché non resti scritta sullo schermo.

Eliminare gli archivi dopo l'estrazione

Con --cleanup, dopo un'estrazione riuscita hoster cancella tutte le parti di quel gruppo (compresi i file di recupero .rev). Se l'estrazione fallisce, non cancella niente.

Quando serve rar

hoster estrae RAR e ZIP da solo, senza programmi esterni. In alcuni casi rari non basta: archivi RAR di formati particolari, ZIP protetti da password, parti danneggiate da riparare con i file .rev. Allora, se sul computer sono installati rar, unrar o 7z, hoster li usa automaticamente e il messaggio dice esterno (rar). Su Debian: sudo apt install 7zip oppure sudo apt install unrar.

Nota

hoster non ripara da solo le parti danneggiate. Se un'estrazione fallisce per una parte rovinata e ci sono i file .rev, si può riparare a mano con rar rc, oppure riscaricare quella parte.

Certificati di sicurezza

Perché ogni tanto compare una nota sui certificati, e a cosa serve -k.

Ogni collegamento sicuro (https) si basa su un certificato che il sito presenta per dimostrare chi è. Alcuni server da cui partono i download (per esempio quelli di terabytez) presentano un certificato incompleto: i browser lo accettano lo stesso, i programmi più severi no. hoster se ne accorge e, solo per quel server, prosegue senza quella verifica, avvisando con una riga:

nota: fs12.terabytez.org:183 ha una catena di certificati incompleta — verifica TLS saltata per questo host

Tutti gli altri siti restano verificati, e un certificato scaduto o intestato a un altro sito viene comunque rifiutato. Non devi fare niente.

L'opzione -k (o --insecure) salta la verifica per tutti i siti. Di norma non serve: tienila per casi eccezionali e sapendo che toglie una protezione.

Siti supportati

Quali siti funzionano e cosa fare con uno nuovo.

L'elenco

Molti siti di file hosting usano lo stesso programma lato server, XFileSharing: per questo un solo meccanismo li copre quasi tutti.

SitoStato
terabytez.orgprovato login, link diretti, download completo ed estrazione del set Kali (15 parti, ~18 GB).
filestore.meprovato link con codice al posto del nome: nome vero ricavato dal server.
worldbytez.com, ddownload.com, clicknupload.to, dropapk.to, send.cm, userupload.net, usersdrive.com, uploadrar.com, file-upload.orgStesso sistema, dovrebbero funzionare allo stesso modo; non ancora provati.

Provare un sito nuovo

  1. Aggiungi la riga del sito in account e un suo link in links.
  2. Prova senza scaricare: ./hoster --dry-run. Se compare ✓, il sito funziona: puoi scaricare normalmente.
  3. Se compare ✗, rilancia con ./hoster --dry-run --debug dbg: hoster salva nella cartella dbg le pagine che ha ricevuto a ogni passo. Con quelle pagine il resolver si può adattare al sito (lo spiega il manuale tecnico).
Attenzione

Le pagine salvate da --debug sono quelle che vedi da utente collegato: possono contenere il tuo nome utente, la tua email o dati del tuo account. Non pubblicarle senza averle guardate.

Problemi e soluzioni

Ogni messaggio di errore, cosa vuol dire e cosa fare.

Il programma si ferma subito

Questi messaggi iniziano con hoster: e fermano il programma prima di cominciare.

MessaggioCosa vuol dire e cosa fare
hoster: account: open account: no such file or directory Non c'è il file account nella cartella da cui hai lanciato il programma. Crealo (dal modello account.example) o indicalo con -a.
hoster: link: open links: no such file or directory Manca il file dei link. Crealo o indicalo con -i.
hoster: nessun link in links Il file c'è ma contiene solo righe vuote o commenti.
hoster: account: riga 3 non valida (manca ':' o ';') La riga indicata del file account non ha separatori. Formato giusto: dominio:utente:password.
hoster: account: riga 3: manca il separatore tra utente e password C'è un solo separatore: manca l'utente o la password.
hoster: account: riga 3: dominio o utente vuoto La riga inizia con un separatore, o l'utente è vuoto (per esempio sito.org::password).
hoster: dimensione non valida: "2X" Il valore di --rate non è un numero con un'unità valida (k, M, G).
flag provided but not defined: -zz Opzione sconosciuta (il messaggio è in inglese perché viene dalla libreria standard). Subito dopo compare la guida con le opzioni giuste.

Un link non si risolve

Questi messaggi compaiono accanto a ✗ per un singolo link; gli altri link proseguono.

MessaggioCosa vuol dire e cosa fare
nessun account nel file 'account' per sito.com Manca la riga di quel sito in account, o il nome è scritto diversamente.
login non riuscito su sito.com (credenziali errate, captcha o pagina diversa: usa -debug) Controlla utente e password entrando nel sito con il browser. Se lì funzionano, il sito potrebbe chiedere un captcha al login o avere una pagina diversa dal solito: prova con --debug (vedi Provare un sito nuovo).
apertura login: … no such host, … connection refused, … timeout Il sito non si raggiunge: connessione assente, nome del sito sbagliato, o sito fuori servizio.
countdown rilevato: l'account non risulta premium su sito.com Il sito mostra l'attesa riservata agli utenti gratuiti: l'account non è premium, o il premium è scaduto. hoster non aggira le attese.
link diretto non trovato (forse file solo-premium, o resolver da rifinire: usa -debug) La pagina parla di premium ma il link non c'è: spesso un account senza premium attivo. Altrimenti il sito va adattato con --debug.
link diretto non trovato (rifinisci il resolver con -debug) Il file potrebbe essere stato rimosso (controlla il link nel browser), oppure il sito ha una pagina che hoster non conosce ancora.
URL non validoLa riga in links non è un indirizzo web.

Un download fallisce

MessaggioCosa vuol dire e cosa fare
HTTP 403, HTTP 404, HTTP 410 Il server rifiuta il file anche dopo aver rigenerato il link 2 volte. Riprova più tardi con -c; se continua, apri il link nel browser.
HTTP 429, HTTP 503 Il sito è sovraccarico o limita i download contemporanei: riprova con meno file insieme, per esempio -j 2.
download incompleto: 734003200/1288490188 byte Il server ha chiuso prima della fine per tutti i tentativi. Rilancia con -c per riprendere.
connection reset, unexpected EOF, timeout Rete instabile. Rilancia con -c; su reti molto instabili aumenta --retries e --timeout.
no space left on deviceIl disco è pieno. Libera spazio e rilancia con -c.

L'estrazione fallisce

MessaggioCosa vuol dire e cosa fare
estrazione fallita (password errata, parti mancanti o formato non supportato) Nessuna password ha funzionato, oppure manca una parte, oppure l'archivio è danneggiato. Controlla che ci siano tutte le parti; prova la password con -p; installa 7zip o unrar per i formati particolari.
estrazione: nessun archivio in downloads Nella cartella non ci sono file .rar o .zip.
percorso non sicuro nell'archivio L'archivio prova a scrivere fuori dalla cartella di destinazione: hoster si rifiuta di estrarlo. Non fidarti del contenuto.

Altre situazioni

I download sono lenti
Controlla di non aver dato --rate. Alcuni siti limitano la velocità per singolo file: più file insieme (-j) aiutano; se il sito lo permette, anche -s.
Non vedo le barre, solo righe di testo
Succede quando l'uscita non va su un terminale (per esempio se la mandi in un file): è voluto, e le righe di testo sono più adatte a un file di registro.
Voglio l'uscita senza colori
Imposta la variabile NO_COLOR: NO_COLOR=1 ./hoster.
Lo uso in uno script
Attenzione: se qualche download fallisce, hoster termina comunque con stato 0 («riuscito»). Per accorgersene bisogna leggere la riga finale scaricati: N falliti: M. Vedi Stati di uscita.

Recupero su un nuovo dispositivo

Se il tablet o il computer si guasta: come rimettere tutto in piedi da zero.

Ripartire da zero

  1. Scarica il progetto: 
    $ git clone https://github.com/nic-fio/HOSTER.git
$ cd HOSTER
  2. Prepara la macchina (installa Go e il resto, chiede sudo): 
    $ tools/setup-dev.sh --install
    Lo script dice anche quali file personali mancano.
  3. Costruisci e controlla: 
    $ make
$ make test
  4. Ricrea i file personali: 
    $ cp account.example account
$ nano account
$ chmod 600 account
  5. Verifica con build/hoster --dry-run.

Se non vuoi installare niente, basta il programma pronto della release (vedi Il programma pronto) più il file account.

Un backup che non dipende da GitHub

tools/backup.sh salva l'intero progetto, con tutta la storia, in un solo file che si ripristina anche senza rete:

$ tools/backup.sh /media/chiavetta
$ git clone /media/chiavetta/hoster-2026-09-24.bundle HOSTER

Con --personal salva accanto anche un archivio con account, links e passwords.txt:

$ tools/backup.sh --personal /media/chiavetta
Attenzione

L'archivio dei file personali contiene le password in chiaro. Tienilo solo su supporti tuoi (una chiavetta, un disco esterno) e mai su servizi pubblici. Un'alternativa comoda è tenere le credenziali dei siti nel tuo gestore di password.

Riferimento delle opzioni

Tutte le opzioni, con il valore usato se non le indichi. Si possono scrivere con uno o due trattini: -dry-run e --dry-run sono la stessa cosa.

Download

-i FILE
File con i link da scaricare, uno per riga. Normale: links.
-a FILE
File degli account, dominio:utente:password. Normale: account.
-d DIR
Cartella in cui salvare i file (creata se non c'è). Normale: downloads.
-s N
Connessioni per file. Normale: 1. Vedi Connessioni per file.
-j N
File scaricati insieme, e grandezza dei gruppi di link. Normale: 5.
-c
Riprende i download interrotti da dove si erano fermati. Riscarica però anche i file già completi: vedi Interruzioni e ripresa.
--rate SIZE
Limite di banda complessivo, per esempio 2M. Normale: 0, nessun limite.
--timeout SEC
Secondi di attesa massima per il collegamento e la prima risposta del server durante un download. Normale: 60.
--retries N
Nuovi tentativi per ciascun download dopo il primo. Normale: 5.
--retry-wait SEC
Secondi di attesa tra un tentativo e il successivo. Normale: 2.
-U UA
Come hoster si presenta ai siti (lo User-Agent), per login e download. Normale: quello di Firefox 128 su Linux. Da cambiare solo se un sito lo richiede.
-k, --insecure
Salta la verifica dei certificati di sicurezza per tutti i siti. Di norma non serve: vedi Certificati di sicurezza.

Estrazione

-e, --extract
Finiti i download, estrae gli archivi RAR e ZIP della cartella dei download.
--extract-only DIR
Estrae soltanto gli archivi di DIR ed esce, senza scaricare.
-p PASS
Password degli archivi.
--pwfile FILE
File di password da provare, una per riga. Normale: passwords.txt (se non esiste, viene ignorato).
--cleanup
Dopo un'estrazione riuscita cancella tutte le parti dell'archivio.

Diagnostica

--dry-run
Fa il login e ricava i link diretti, stampandoli, senza scaricare.
--debug DIR
Salva in DIR le pagine ricevute a ogni passo di login e risoluzione. Vedi Provare un sito nuovo.
-v, --verbose
Mostra anche il link diretto trovato per ogni file (righe con →).
-qe
Uscita ridotta: niente barre né messaggi per i singoli file. Restano gli errori che fermano il programma, il conteggio finale scaricati/falliti e i messaggi dell'estrazione.
-qa
Come -qe, senza nemmeno il conteggio finale. Gli errori che fermano il programma e i messaggi dell'estrazione compaiono comunque.
-h, --help
Mostra la guida integrata.

Glossario

File hosting
Sito dove si caricano file per farli scaricare ad altri, con un link per ogni file.
Premium
Account a pagamento: download senza attese né captcha, spesso a velocità piena.
Link diretto
L'indirizzo da cui parte davvero il file, diverso dalla pagina del file. Dura poco.
XFileSharing
Il programma usato da molti siti di file hosting: per questo si comportano quasi allo stesso modo.
Archivio in parti
Un archivio diviso in più file (part01, part02…) da estrarre insieme.
File .rev
File di recupero di un archivio RAR: permettono di ricostruire una parte danneggiata o mancante.
Certificato
Il documento digitale con cui un sito https dimostra la propria identità.
Release
Una versione pubblicata del programma, con il file pronto da scaricare.
