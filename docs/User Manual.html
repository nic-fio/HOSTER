    Chapter 1

    Welcome

    1.1 · What hoster is

    hoster is a terminal program for downloading files from file hosting sites (terabytez, filestore, worldbytez and the like) using your own accounts. It does what you would do by hand in the browser — signing in with username and password, opening each link, clicking «download» — but for all the links at once, without you having to touch anything.

    It is designed like JDownloader, but without Java: it is a single executable file and does not need anything else installed. In short:

    1.2 · What it does not do

    hoster uses only the «premium» route: the one the site offers to those who have a paid account and sign in. It does not bypass captchas, waiting times or limits of free sites. If a site asks you to wait for a countdown, hoster stops and tells you that the account does not appear to be premium.

    i
    Intended use. Downloading, with your own accounts, content you are authorized to download — for example the images of a Linux distribution — just as you would with JDownloader.

    1.3 · How it works, in brief

    hoster reads your accounts and the list of links, signs in to each site only once, works out for each file its direct link (the address the file actually comes from) and downloads. At the end, if you ask it to, it extracts the archives.

    The sites' direct links expire quickly, so hoster works in batches: it takes 5 links (or as many as you specify with -j), works out their direct links, downloads them together and only then moves on to the next 5 (see How many files at once).

    1.4 · How to use this manual

    The Search box at the top of the side contents finds a word anywhere in the manual (the / key takes you straight there); the index at the end lists options, files and topics.

    1.5 · Conventions

    Chapter 2

    Installation and first run

    2.1 · Requirements

    2.2 · The ready-made program, with git clone

    The repository already contains the compiled program, the file hoster (for PCs and tablets with an Intel or AMD processor). Just clone it:

    $ git clone https://github.com/nic-fio/HOSTER.git
$ cd HOSTER
$ ./hoster --help

    There is nothing else to install. The cloned folder can directly become your working folder: the personal files (account, links, passwords.txt) and downloads/ are excluded from the repository, so they never end up on GitHub by mistake.

    2.3 · Just the program, from the releases

    If you do not want to clone, the releases page on GitHub has two files:

    If you do not know which one you need, the command uname -m tells you: x86_64 means amd64, aarch64 means arm64. Once the file is downloaded, create a working folder and put it there:

    1. Create the working folder and go into it.
    2. Move the downloaded file there, naming it simply hoster.
    3. Make it executable with chmod +x and check that it starts.
    $ mkdir ~/hoster && cd ~/hoster
$ mv ~/Scaricati/hoster-linux-amd64 hoster
$ chmod +x hoster
$ ./hoster --help

    2.4 · From the source code

    You need a Debian or Ubuntu machine with an Internet connection. The script tools/setup-dev.sh checks for and installs whatever is missing (the Go compiler and a few other packages; it asks for the password for sudo):

    $ git clone https://github.com/nic-fio/HOSTER.git
$ cd HOSTER
$ tools/setup-dev.sh --install
$ make
$ make test

    make rebuilds the hoster program from the code; make test runs all the automatic checks. You only need this if you want to modify hoster, or to use it on an ARM computer with the code at hand: the ready-made program in the repository is for Intel and AMD processors.

    2.5 · Where it looks for its files

    hoster looks for account, links and passwords.txt in the folder you run it from (not in the one where the program is), and saves the downloads in downloads/ inside that same folder. The simplest way is to keep everything together in one folder and run ./hoster from there:

    HOSTER/
├── hoster          the program
├── account         your accounts (you create it)
├── links           the links to download (you create it)
├── passwords.txt   archive passwords (optional)
└── downloads/      the files arrive here (created by hoster)

    With the options -a, -i, --pwfile and -d you can specify different files and folders.

    2.6 · Updating hoster

    If you cloned the repository, to move to the latest version all you need is, from the hoster folder:

    $ git pull

    The ready-made program is in the repository, so it arrives updated together with everything else. Your personal files are not touched: they are not part of the repository. If instead you downloaded the program from the releases, download the file of the new version and replace the old hoster (remembering chmod +x). To find out which version you have, look at the last line of the guide in text form: ./hoster --help | tail -n 1 shows, for example, hoster 1.0.

    Help is always at hand, even without this manual.

    ./hoster --help (or -h, -help, or simply ./hoster help) opens a tabbed guide in the terminal with all the options, the known sites and some ready-made examples. The guide does not download anything: you close it with q and the program ends.

    If the terminal is too small (fewer than 44 columns or 10 rows), the same guide appears as text in the format of manual pages, which you can page through with less (or with the program named in the PAGER variable). If the output does not go to a screen, for example

    Chapter 4

    First steps

    4.1 · The path

    From the freshly installed program to the first downloaded file, in four steps.

    1. Write the accounts in the account file, one line per site (chapter 4.2).
    2. Write the links in the links file, one per line (chapter 4.3).
    3. Try without downloading with ./hoster --dry-run, to check accounts and links (chapter 4.4).
    4. Download with ./hoster, or download and extract with ./hoster -e -p LAPASSWORD (chapter 4.5).

    4.2 · The account file

    One line for each site, with domain, username and password separated by colons:

    # Lines starting with # are comments.
terabytez.org:mariorossi:la-mia-password
filestore.me:mrossi;altra:password;con:simboli
    • Instead of the colon : the semicolon ; also works, even mixed.
    • Only the first two separators count: the password is the whole rest of the line, so it can contain :, ; and any other character. In the example, the password for the second site is altra:password;con:simboli.
    • Do not put spaces around the separators: a space after the second separator would become part of the password.
    • The domain can also be written without its final part: terabytez:utente:password (utente = username) applies to both terabytez.org and terabytez.com. You can also write www. in front or the full address with https://: they are ignored.
    • Blank lines and lines starting with # are skipped.

    The repository contains a template, account.example: copy it to account and replace the data.

    $ cp account.example account
$ nano account
$ chmod 600 account
    !
    Warning. The account file contains your passwords in plain text. Do not share it and do not upload it to GitHub: hoster's repository is configured to ignore it, but a copy placed elsewhere is not protected. It is best to make the file readable only by you: chmod 600 account.

    4.3 · The links file

    One link per line, just as you copy it from the browser. Blank lines and lines starting with # are skipped, and if the same link appears twice it is downloaded only once.

    # Kali, complete set
https://terabytez.org/abc123def456/kali-linux.part01.rar
https://terabytez.org/ghi789jkl012/kali-linux.part02.rar
https://filestore.me/nhail4vmw015

    The links can be from different sites, mixed together: hoster signs in to each one the first time it needs to. The files are processed in the order in which they appear. Here too there is a template, links.example.

    +
    Tip. To keep a link aside without downloading it, put a # in front of it: it stays in the file but is skipped.

    4.4 · Trying without downloading

    Before a long download it is worth checking that sign-in and links work. With --dry-run hoster signs in to the sites, works out the direct links and shows them, without downloading anything:

    $ ./hoster --dry-run
✓ kali-linux.part01.rar
  https://terabytez.org/abc123def456/kali-linux.part01.rar
✓ debian-12.iso
  https://filestore.me/nhail4vmw015

risolti: 2  falliti: 0

    Each line with ✓ is a file ready to be downloaded, with its real name and the address it will come from (with premium accounts this is often the same as the original link, because the site sends the file directly). The last line counts the links resolved (risolti) and failed (falliti). A line with ✗ says what is wrong, for example («no account in the 'account' file for altrosito.com»):

    ✗ https://altrosito.com/abc123
  nessun account nel file 'account' per altrosito.com

    The Troubleshooting chapter explains every message.

    4.5 · The first download

    $ ./hoster
 ✓ kali-linux.part01.rar  1.2G
 ⬇ kali-linux.part02.rar        ▕████████████░░░░░░░░░░░░░░░░▏ 43%  512M/1.2G  92.0M/s  7s
 ⬇ kali-linux.part03.rar        ▕█████▉░░░░░░░░░░░░░░░░░░░░░░▏ 21%  250M/1.2G  88.0M/s  11s
 2 in corso · 1 completati

    At the end the summary appears, with the number of files, the total size, the time taken and the average speed (media), then the count of downloaded (scaricati) and failed (falliti) files:

    ✓ 15 file · 17.6G in 3m21s · media 89.7M/s
scaricati: 15  falliti: 0

    The files are in downloads/. While a file is in progress it is called NOME.part (where NOME is its name); it takes its final name only when it is complete and checked.

    +
    Tip. To download and extract in one go: ./hoster -e -p LAPASSWORD. See Extracting archives.
    Chapter 5

    Downloading

    5.1 · How many files at once

    By default hoster downloads 5 files at a time. With -j you choose a different number: -j 2 for a slow connection or for a site that does not like too many simultaneous downloads, -j 10 if the line can take it.

    The same number also sets the size of the batches: hoster works out the direct links of a batch, downloads all of it and moves on to the next batch only when the last file of the batch has finished. This way the direct links are used straight away, before they expire.

    5.2 · Connections per file

    Each file is downloaded over a single connection, which is what premium accounts usually allow. If a site allows several connections on the same file, -s 4 splits each file into 4 pieces downloaded together. This applies only to files of at least 1 MB and only if the site accepts downloads «in pieces»; otherwise hoster uses a single connection anyway. The file still has just one bar even with several connections.

    5.3 · Interruptions and resuming

    If the connection drops during a file, hoster retries on its own up to 5 times (option --retries), waiting 2 seconds between one attempt and the next (--retry-wait), and restarts from the point it had reached, without starting over from the beginning when the site allows it.

    If instead you interrupt the program yourself (Ctrl+C), or the computer shuts down, run it again with -c:

    $ ./hoster -c

    Half-finished files (.part) resume from where they had got to, if the site accepts downloads «in pieces»; otherwise they start again from zero.

    !
    Good to know. With -c files that are already complete are downloaded again as well. If the list contains files that have already finished, it is best to remove them from links (or comment them out with #) before running again with -c.

    5.4 · Expired links

    A direct link is valid only for a short time. If it expires while the file is queued or half-way through, the site responds with a refusal; hoster notices, goes back to the original page of the file, works out a new link and carries on. It does this up to 2 times per file and reports it with a line («note: direct link expired, regenerating it»):

    nota: link diretto scaduto, lo rigenero (kali-linux.part07.rar)

    You do not need to do anything: the file is not counted as failed.

    5.5 · File names and duplicates

    Some sites put the file name in the link (…/kali-linux.part01.rar), others only a code (https://filestore.me/nhail4vmw015). hoster looks for the real name in the file's page, in the direct link and finally in what the server declares at the start of the download, and always saves under the real name.

    If two links lead to the same file (for example the same archive on two different sites), the second one is skipped with the line • nome (duplicato, ignorato), that is «duplicate, ignored».

    5.6 · Limiting bandwidth

    --rate sets an overall limit, valid for all downloads together:

    $ ./hoster --rate 2M

    The units are k, M, G and T (lowercase too) and they mean bytes per second: 2M is about 2 megabytes per second, that is about 16 megabits. Decimals are allowed (1.5M) and a number without a unit is in bytes. 0, the default value, means no limit.

    5.7 · Slow or unstable networks

    --timeout (60 seconds) is the maximum time to wait for a server to respond at the start of a download. It does not limit how long the download takes: a file of many gigabytes can take as long as it needs. On a very slow network it can be raised, for example --timeout 120, together with --retries 10:

    $ ./hoster --timeout 120 --retries 10 --retry-wait 10

    5.8 · Another folder or another list

    $ ./hoster -i kali.txt -d /media/disco/iso

    Uses the list kali.txt instead of links and saves to /media/disco/iso (created if it does not exist). In the same way -a specifies another accounts file.

    5.9 · More or fewer messages

    When the output does not go to a terminal (for example if you send it to a file) the bars do not appear: in their place there are simple lines of text, better suited to a log file.

    Chapter 6

    Extracting archives

    6.1 · Downloading and extracting

    $ ./hoster -e -p LAPASSWORD

    With -e, once the downloads have finished, hoster extracts all the RAR and ZIP archives it finds in the download folder, into that same folder:

    == estrazione ==
• kali-linux.part01.rar
  ✓ estratto (integrato, password trovata)

    Under the heading «estrazione» (extraction), for each archive the name and the outcome appear («estratto» means extracted, «password trovata» password found): integrato (built-in) means that hoster did it on its own, esterno (rar) (external) that it got help from an installed program (chapter 6.6).

    !
    Warning. If the folder already contains a file with the same name as one inside the archive, it is replaced.

    6.2 · Extracting an already downloaded folder

    $ ./hoster --extract-only downloads -p LAPASSWORD

    It does not download anything and does not need account or links: it extracts the archives in downloads and exits. --pwfile and --cleanup apply as well.

    6.3 · Multi-part archives

    A large archive is often split into parts: nome.part01.rar, nome.part02.rar… hoster recognizes the set and extracts it only once, starting from the first part. All the parts must be in the same folder: if one is missing, the extraction of that set fails (the others carry on).

    6.4 · Passwords

    For each archive hoster tries, in this order:

    1. No password (many archives do not have one).
    2. The password given with -p, if any.
    3. The passwords in the passwords.txt file, one per line, from top to bottom (blank lines and lines with # are skipped). The file is optional; --pwfile specifies a different one.

    The final message says whether a password was needed (password trovata, password found) but not which one, so that it does not remain written on the screen.

    +
    Tip. If you often download archives with the same passwords, write them in passwords.txt: you will no longer need to give them with -p. Like account, this file also stays out of the repository.

    6.5 · Deleting archives after extraction

    With --cleanup, after a successful extraction hoster deletes all the parts of that set (including the .rev recovery files) and reports it with · archivi del set rimossi (set archives removed). If the extraction fails, it deletes nothing.

    6.6 · When rar is needed

    hoster extracts RAR and ZIP on its own, without external programs. In a few rare cases this is not enough: RAR archives in unusual formats, password-protected ZIPs, damaged parts to be repaired with the .rev files. In those cases, if rar, unrar or 7z are installed on the computer, hoster uses them automatically and the message says esterno (rar) (or the name of the program used). On Debian:

    $ sudo apt install 7zip
# or
$ sudo apt install unrar
    i
    Note. hoster does not repair damaged parts on its own. If an extraction fails because of a corrupted part and the .rev files are there, you can repair it by hand with rar rc, or download that part again.
    Chapter 7

    Security certificates

    7.1 · Why a note about certificates appears

    Every secure connection (https) relies on a certificate that the site presents to prove who it is. Some of the servers that downloads come from (for example those of terabytez) present an incomplete certificate: browsers accept it anyway, stricter programs do not. hoster notices this and, only for that server, carries on without that check, warning you with a line («note: … has an incomplete certificate chain — TLS verification skipped for this host»):

    nota: fs12.terabytez.org:183 ha una catena di certificati incompleta — verifica TLS saltata per questo host

    All other sites are still verified, and a certificate that has expired or was issued to a different site is rejected in any case. You do not need to do anything.

    7.2 · Forcing with -k

    The -k option (or --insecure) skips the check for all sites.

    !
    Warning. Normally -k is not needed: keep it for exceptional cases, knowing that it removes a protection from all connections, including the one that carries your username and password.
    Chapter 8

    Supported sites

    8.1 · The list

    Many file hosting sites use the same server-side program, XFileSharing: that is why a single mechanism covers almost all of them. To use one, you just add its line to the account file.

    8.2 · Trying a new site

    1. Add the site's line to account and one of its links to links.
    2. Try without downloading: ./hoster --dry-run. If ✓ appears, the site works: you can download normally.
    3. If ✗ appears, run again with ./hoster --dry-run --debug dbg: hoster saves in the dbg folder the pages it received at each step. With those pages the program can be adapted to the site (the Technical Manual explains how).
    !
    Warning. The pages saved by --debug are the ones you see as a signed-in user: they may contain your username, your email or data from your account. Do not publish them without having looked at them.
    Chapter 9

    Recovery on a new device

    9.1 · What is saved and where

    If the tablet or the computer breaks down, everything can be set up again from scratch in a few minutes.

    9.2 · Starting over from scratch

    1. Get the project: git clone https://github.com/nic-fio/HOSTER.git, then cd HOSTER.
    2. Recreate the personal files: cp account.example account, write in your data (for example with nano account) and protect it with chmod 600 account. Do the same for links and, if needed, passwords.txt.
    3. Check with ./hoster --dry-run. Done: the program is already in the repository.
    $ git clone https://github.com/nic-fio/HOSTER.git
$ cd HOSTER
$ cp account.example account
$ nano account
$ chmod 600 account
$ ./hoster --dry-run

    If you also want to be able to modify and rebuild hoster, prepare the machine (it installs Go and the rest, and asks for sudo) and check that everything works:

    $ tools/setup-dev.sh --install
$ make
$ make test

    9.3 · A backup that does not depend on GitHub

    tools/backup.sh saves the entire project, with its whole history, into a single file that can be restored even without a network:

    $ tools/backup.sh /media/chiavetta
$ git clone /media/chiavetta/hoster-2026-09-24.bundle HOSTER

    The file name contains the date of the backup. With --personal it also saves, alongside it, an archive with account, links and passwords.txt:

    $ tools/backup.sh --personal /media/chiavetta
    !
    Warning. The archive of personal files contains the passwords in plain text. Keep it only on media of your own (a USB stick, an external disk) and never on public services. A convenient alternative is to keep the sites' credentials in your password manager.
    Chapter 10

    Option reference

    All the options, with the value used if you do not specify them. They can be written with one or two dashes: -dry-run and --dry-run are the same thing. Options can be combined freely: ./hoster -j 3 --rate 5M -e -p PW.

    10.1 · Download

    -i FILE
    File with the links to download, one per line. Default: links. See The links file.
    -a FILE
    Accounts file, dominio:utente:password (domain:username:password). Default: account. See The account file.
    -d DIR
    Folder in which to save the files (created if it does not exist). Default: downloads.
    -s N
    Connections per file. Default: 1. See Connections per file.
    -j N
    Files downloaded at once, and size of the batches of links. Default: 5. See How many files at once.
    -c
    Resumes interrupted downloads from where they stopped. However, it also downloads files that are already complete again: see Interruptions and resuming.
    --rate SIZE
    Overall bandwidth limit, for example 2M. Default: 0, no limit. See Limiting bandwidth.
    --timeout SEC
    Maximum seconds to wait for the connection and for the server's first response during a download. Default: 60.
    --retries N
    New attempts for each download after the first one. Default: 5.
    --retry-wait SEC
    Seconds to wait between one attempt and the next. Default: 2.
    -U UA
    How hoster presents itself to the sites (the User-Agent), for sign-in and download. Default: that of Firefox 128 on Linux. Change it only if a site requires it.
    -k, --insecure
    Skips the check of security certificates for all sites. Normally not needed: see Security certificates.

    10.2 · Extraction

    -e, --extract
    Once the downloads have finished, extracts the RAR and ZIP archives in the download folder.
    --extract-only DIR
    Only extracts the archives in DIR and exits, without downloading.
    -p PASS
    Archive password. See Passwords.
    --pwfile FILE
    File of passwords to try, one per line. Default: passwords.txt (ignored if it does not exist).
    --cleanup
    After a successful extraction, deletes all the parts of the archive.

    10.3 · Diagnostics

    --dry-run
    Signs in and works out the direct links, printing them, without downloading. See Trying without downloading.
    --debug DIR
    Saves in DIR the pages received at each step of sign-in and of the search for the direct link. See Trying a new site.
    -v, --verbose
    Also shows the direct link found for each file (lines with →).
    -qe
    Reduced output: no bars or messages for individual files. What remains: errors that stop the program, the final count scaricati/falliti (downloaded/failed) and the extraction messages.
    -qa
    Like -qe, without even the final count. Errors that stop the program and the extraction messages appear anyway.
    -h, --help
    Shows the built-in guide.

    10.4 · Files used

    10.5 · Exit statuses

    The number hoster returns when it ends, useful if you run it from a script:

    10.6 · Ready-made examples

    # download the links in 'links' into ./downloads with the accounts in 'account'
$ ./hoster

# use a different list and destination folder
$ ./hoster -i kali.txt -d /media/iso

# work out the direct links without downloading (check)
$ ./hoster --dry-run

# download and then extract the archives with the given password
$ ./hoster -e -p LAPASSWORD

# extract an already downloaded folder
$ ./hoster --extract-only downloads -p PW

# resume after an interruption, with fewer files at once and limited bandwidth
$ ./hoster -c -j 2 --rate 3M

    11.1 · The program stops immediately

    Note. In the messages about accounts the faulty line appears in quotation marks, password included: be careful if you copy the message to ask for help.

    11.2 · A link does not resolve

    These messages appear next to ✗ for a single link; the other links carry on.

    11.3 · A download fails

    11.4 · Extraction fails

    11.5 · Other situations

    Downloads are slow
    Check that you have not given --rate. Some sites limit the speed per file: more files at once (-j) help; if the site allows it, so does -s.
    I don't see the bars, only lines of text
    This happens when the output does not go to a terminal (for example if you send it to a file): it is intentional, and lines of text are better suited to a log file. Also check that you have not given -qe or -qa.
    I want output without colors
    Set the NO_COLOR variable: NO_COLOR=1 ./hoster.
    A file already downloaded is downloaded again
    This happens with -c (chapter 5.3), or for links with a code instead of the name (chapter 11.6). Remove the files that are already complete from the list.
    I use it in a script
    Careful: if some downloads fail, hoster still ends with status 0 («success»). To notice, you have to read the final line scaricati: N falliti: M (downloaded: N, failed: M). See Exit statuses.

    11.6 · Known limitations

    Known behaviors of version 1.0, to bear in mind:

    • With -c files that are already complete are downloaded again too. Before running again, remove the finished files from the list.
    • Files with a code instead of the name (such as https://filestore.me/nhail4vmw015) are not recognized as already downloaded: they are downloaded again at every run.
    • The exit status is 0 even if some downloads fail: the number of failures is only in the final line.
    • Rarely, if two direct links expire at the same moment, hoster signs in to the site twice. This has no consequences for the downloads.
    Chapter 12

    Glossary

    12.1 · Terms

    Multi-part archive
    An archive split into several files (part01, part02…) to be extracted together. See Ch. 6.
    Certificate
    The digital document with which an https site proves its identity. See Ch. 7.
    Dry run (trial)
    A trial run: sign-in and search for the direct links, without downloading. See Ch. 4.
    .rev file
    Recovery file of a RAR archive: these files make it possible to rebuild a damaged or missing part.
    File hosting
    A site where files are uploaded so that others can download them, with one link for each file.
    Batch
    The links that hoster processes together: as many as specified with -j (normally 5). See Ch. 5.
    Direct link
    The address the file actually comes from, different from the file's page. It does not last long.
    Premium
    Paid account: downloads without waiting times or captchas, often at full speed.
    Release
    A published version of the program, with the ready-made file to download.
    Repository
    The public collection on GitHub with the program, the code, the manuals and their history. It is copied with git clone.
    User-Agent
    The way a program presents itself to sites; hoster presents itself as Firefox. See -U.
    XFileSharing
    The program used by many file hosting sites: that is why they behave in almost the same way.
