    Capitolo 1

    Benvenuto

    1.1 · Che cos'è hoster

    hoster è un programma da terminale per scaricare file dai siti di file hosting (terabytez, filestore, worldbytez e simili) usando i tuoi account. Fa quello che faresti a mano nel browser — entrare con utente e password, aprire ogni link, premere «scarica» — ma per tutti i link insieme, senza che tu debba toccare niente.

    È pensato come JDownloader, ma senza Java: è un unico file eseguibile e non ha bisogno di installare altro. In breve:

    1.2 · Cosa non fa

    hoster usa soltanto il percorso «premium»: quello che il sito offre a chi ha un account a pagamento e fa il login. Non aggira captcha, attese o limiti dei siti gratuiti. Se un sito chiede di aspettare un conto alla rovescia, hoster si ferma e ti dice che l'account non risulta premium.

    i
    Uso previsto. scaricare con i propri account contenuti che si è autorizzati a scaricare — per esempio le immagini di una distribuzione Linux — come si farebbe con JDownloader.

    1.3 · Come funziona, in breve

    hoster legge i tuoi account e la lista dei link, entra in ogni sito una volta sola, ricava per ogni file il suo link diretto (l'indirizzo da cui parte davvero il file) e scarica. Alla fine, se glielo chiedi, estrae gli archivi.

    I link diretti dei siti scadono in fretta, perciò hoster lavora a gruppi: prende 5 link (o quanti ne indichi con -j), ricava i loro link diretti, li scarica insieme e solo dopo passa ai 5 successivi (vedi Quanti file insieme).

    1.4 · Come usare questo manuale

    La casella Cerca in cima all'indice laterale trova una parola in tutto il manuale (il tasto / ci porta direttamente); l'indice analitico in fondo elenca opzioni, file e argomenti.

    1.5 · Convenzioni

    i
    Versione. questo manuale descrive hoster 1.0. Il funzionamento interno è descritto nel Manuale Tecnico; il perché delle scelte fatte è raccolto in decisioni e storia del progetto. Copyright © 2026 nic-fio, tutti i diritti riservati: il codice è pubblico perché si possa leggere e recuperare.
    Capitolo 2

    Installazione e primo avvio

    2.1 · Requisiti

    2.2 · Il programma pronto, con git clone

    Il repository contiene già il programma compilato, il file hoster (per PC e tablet con processore Intel o AMD). Basta clonarlo:

    $ git clone https://github.com/nic-fio/HOSTER.git
$ cd HOSTER
$ ./hoster --help

    Non serve installare altro. La cartella clonata può diventare direttamente la tua cartella di lavoro: i file personali (account, links, passwords.txt) e downloads/ sono esclusi dal repository, quindi non finiscono mai su GitHub per sbaglio.

    2.3 · Solo il programma, dalle release

    Se non vuoi clonare, nella pagina delle release su GitHub ci sono due file:

    Se non sai quale ti serve, il comando uname -m te lo dice: x86_64 vuol dire amd64, aarch64 vuol dire arm64. Scaricato il file, crea una cartella di lavoro e mettilo lì:

    1. Crea la cartella di lavoro ed entraci.
    2. Sposta lì il file scaricato, chiamandolo semplicemente hoster.
    3. Rendilo eseguibile con chmod +x e controlla che parta.
    $ mkdir ~/hoster && cd ~/hoster
$ mv ~/Scaricati/hoster-linux-amd64 hoster
$ chmod +x hoster
$ ./hoster --help

    2.4 · Dal codice sorgente

    Serve una macchina Debian o Ubuntu con connessione a Internet. Lo script tools/setup-dev.sh controlla e installa quello che manca (il compilatore Go e pochi altri pacchetti; chiede la password per sudo):

    $ git clone https://github.com/nic-fio/HOSTER.git
$ cd HOSTER
$ tools/setup-dev.sh --install
$ make
$ make test

    make ricostruisce il programma hoster dal codice; make test esegue tutti i controlli automatici. Serve solo se vuoi modificare hoster, o usarlo su un computer ARM avendo il codice a disposizione: il programma pronto nel repository è per processori Intel e AMD.

    2.5 · Dove cerca i suoi file

    hoster cerca account, links e passwords.txt nella cartella da cui lo lanci (non in quella dove si trova il programma), e salva i download in downloads/ dentro la stessa cartella. Il modo più semplice è tenere tutto insieme in una cartella e lanciare ./hoster da lì:

    HOSTER/
├── hoster          il programma
├── account         i tuoi account (lo crei tu)
├── links           i link da scaricare (lo crei tu)
├── passwords.txt   password degli archivi (facoltativo)
└── downloads/      qui arrivano i file (creata da hoster)

    Con le opzioni -a, -i, --pwfile e -d puoi indicare file e cartelle diversi.

    2.6 · Aggiornare hoster

    Se hai clonato il repository, per passare all'ultima versione basta, dalla cartella di hoster:

    $ git pull

    Il programma pronto è nel repository, quindi arriva aggiornato insieme a tutto il resto. I tuoi file personali non vengono toccati: non fanno parte del repository. Se invece hai scaricato il programma dalle release, scarica il file della nuova versione e sostituisci il vecchio hoster (ricordando chmod +x). Per sapere quale versione hai, guarda l'ultima riga della guida in forma di testo: ./hoster --help | tail -n 1 mostra, per esempio, hoster 1.0.

    Capitolo 4

    Primi passi

    4.1 · Il percorso

    Dal programma appena installato al primo file scaricato, in quattro passi.

    1. Scrivi gli account nel file account, una riga per sito (capitolo 4.2).
    2. Scrivi i link nel file links, uno per riga (capitolo 4.3).
    3. Prova senza scaricare con ./hoster --dry-run, per controllare account e link (capitolo 4.4).
    4. Scarica con ./hoster, oppure scarica ed estrai con ./hoster -e -p LAPASSWORD (capitolo 4.5).

    4.2 · Il file account

    Una riga per ogni sito, con dominio, utente e password separati da due punti:

    # Le righe che iniziano con # sono commenti.
terabytez.org:mariorossi:la-mia-password
filestore.me:mrossi;altra:password;con:simboli
    • Al posto dei due punti : va bene anche il punto e virgola ;, anche mescolati.
    • Solo i primi due separatori contano: la password è tutto il resto della riga, quindi può contenere :, ; e qualunque altro carattere. Nell'esempio, la password del secondo sito è altra:password;con:simboli.
    • Non mettere spazi attorno ai separatori: uno spazio dopo il secondo separatore diventerebbe parte della password.
    • Il dominio si può scrivere anche senza la parte finale: terabytez:utente:password vale sia per terabytez.org sia per terabytez.com. Si può scrivere anche www. davanti o l'indirizzo completo con https://: vengono ignorati.
    • Le righe vuote e quelle che iniziano con # vengono saltate.

    Nel repository c'è un modello, account.example: copialo in account e sostituisci i dati.

    $ cp account.example account
$ nano account
$ chmod 600 account
    !
    Attenzione. il file account contiene le tue password in chiaro. Non condividerlo e non caricarlo su GitHub: il repository di hoster è configurato per ignorarlo, ma una copia messa altrove non è protetta. Conviene rendere il file leggibile solo a te: chmod 600 account.

    4.3 · Il file links

    Un link per riga, così come lo copi dal browser. Le righe vuote e quelle che iniziano con # vengono saltate, e se lo stesso link compare due volte viene scaricato una volta sola.

    # Kali, set completo
https://terabytez.org/abc123def456/kali-linux.part01.rar
https://terabytez.org/ghi789jkl012/kali-linux.part02.rar
https://filestore.me/nhail4vmw015

    I link possono essere di siti diversi, mescolati: hoster fa il login su ognuno la prima volta che gli serve. I file vengono lavorati nell'ordine in cui compaiono. Anche qui c'è un modello, links.example.

    +
    Consiglio. per tenere da parte un link senza scaricarlo, mettigli un # davanti: resta nel file ma viene saltato.

    4.4 · Prova senza scaricare

    Prima di un download lungo conviene controllare che login e link funzionino. Con --dry-run hoster entra nei siti, ricava i link diretti e li mostra, senza scaricare niente:

    $ ./hoster --dry-run
✓ kali-linux.part01.rar
  https://terabytez.org/abc123def456/kali-linux.part01.rar
✓ debian-12.iso
  https://filestore.me/nhail4vmw015

risolti: 2  falliti: 0

    Ogni riga con ✓ è un file pronto da scaricare, con il suo nome vero e l'indirizzo da cui partirà (con gli account premium spesso coincide con il link originale, perché il sito manda direttamente il file). Una riga con ✗ dice cosa non va, per esempio:

    ✗ https://altrosito.com/abc123
  nessun account nel file 'account' per altrosito.com

    Il capitolo Risoluzione dei problemi spiega ogni messaggio.

    4.5 · Il primo download

    $ ./hoster
 ✓ kali-linux.part01.rar  1.2G
 ⬇ kali-linux.part02.rar        ▕████████████░░░░░░░░░░░░░░░░▏ 43%  512M/1.2G  92.0M/s  7s
 ⬇ kali-linux.part03.rar        ▕█████▉░░░░░░░░░░░░░░░░░░░░░░▏ 21%  250M/1.2G  88.0M/s  11s
 2 in corso · 1 completati

    Alla fine compare il riepilogo:

    ✓ 15 file · 17.6G in 3m21s · media 89.7M/s
scaricati: 15  falliti: 0

    I file sono in downloads/. Mentre un file è in corso si chiama NOME.part; prende il nome definitivo solo quando è completo e controllato.

    +
    Consiglio. per scaricare ed estrarre in un colpo solo: ./hoster -e -p LAPASSWORD. Vedi Estrarre gli archivi.
    Capitolo 5

    Scaricare

    5.1 · Quanti file insieme

    Di norma hoster scarica 5 file alla volta. Con -j scegli un numero diverso: -j 2 per una connessione lenta o per un sito che non ama troppi download contemporanei, -j 10 se la linea regge.

    Lo stesso numero decide anche la grandezza dei gruppi: hoster ricava i link diretti di un gruppo, lo scarica tutto e passa al gruppo successivo solo quando l'ultimo file del gruppo è finito. Così i link diretti vengono usati subito, prima che scadano.

    5.2 · Connessioni per file

    Ogni file viene scaricato con una sola connessione, che è quello che gli account premium concedono di solito. Se un sito permette più connessioni sullo stesso file, -s 4 divide ogni file in 4 pezzi scaricati insieme. Vale solo per file da almeno 1 MB e solo se il sito accetta download «a pezzi»; altrimenti hoster usa comunque una connessione. La barra del file resta una sola anche con più connessioni.

    5.3 · Interruzioni e ripresa

    Se la connessione cade durante un file, hoster riprova da solo fino a 5 volte (opzione --retries), aspettando 2 secondi tra un tentativo e l'altro (--retry-wait), e riparte dal punto a cui era arrivato, senza ricominciare da capo quando il sito lo permette.

    Se invece interrompi tu il programma (Ctrl+C), o si spegne il computer, rilancialo con -c:

    $ ./hoster -c

    I file rimasti a metà (.part) ripartono da dove erano arrivati, se il sito accetta download «a pezzi»; altrimenti ricominciano da zero.

    !
    Da sapere. con -c anche i file già completi vengono scaricati di nuovo. Se nella lista ci sono file già finiti, conviene toglierli da links (o commentarli con #) prima di rilanciare con -c.

    5.4 · Link scaduti

    Un link diretto vale per poco tempo. Se scade mentre il file è in coda o a metà, il sito risponde con un rifiuto; hoster se ne accorge, torna alla pagina originale del file, ricava un link nuovo e continua. Lo fa fino a 2 volte per file e lo segnala con una riga:

    nota: link diretto scaduto, lo rigenero (kali-linux.part07.rar)

    Non devi fare niente: il file non viene contato come fallito.

    5.5 · Nomi dei file e doppioni

    Alcuni siti mettono il nome del file nel link (…/kali-linux.part01.rar), altri solo un codice (https://filestore.me/nhail4vmw015). hoster cerca il nome vero nella pagina del file, nel link diretto e infine in quello che dichiara il server all'inizio del download, e salva sempre con il nome vero.

    Se due link portano allo stesso file (per esempio lo stesso archivio su due siti diversi), il secondo viene saltato con la riga • nome (duplicato, ignorato).

    5.6 · Limitare la banda

    --rate fissa un limite complessivo, valido per tutti i download insieme:

    $ ./hoster --rate 2M

    Le unità sono k, M, G e T (anche minuscole) e valgono byte al secondo: 2M è circa 2 megabyte al secondo, cioè circa 16 megabit. Sono ammessi i decimali (1.5M) e un numero senza unità vale in byte. 0, il valore normale, vuol dire nessun limite.

    5.7 · Reti lente o instabili

    --timeout (60 secondi) è il tempo massimo di attesa perché un server risponda all'inizio di un download. Non limita la durata del download: un file di molti gigabyte può durare quanto serve. Su una rete molto lenta si può alzare, per esempio --timeout 120, insieme a --retries 10:

    $ ./hoster --timeout 120 --retries 10 --retry-wait 10

    5.8 · Un'altra cartella o un'altra lista

    $ ./hoster -i kali.txt -d /media/disco/iso

    Usa la lista kali.txt al posto di links e salva in /media/disco/iso (creata se non c'è). Allo stesso modo -a indica un altro file di account.

    5.9 · Più o meno messaggi

    Quando l'uscita non va su un terminale (per esempio se la mandi in un file) le barre non compaiono: al loro posto ci sono semplici righe di testo, più adatte a un file di registro.

    Capitolo 6

    Estrarre gli archivi

    6.1 · Scaricare ed estrarre

    $ ./hoster -e -p LAPASSWORD

    Con -e, finiti i download, hoster estrae tutti gli archivi RAR e ZIP che trova nella cartella dei download, nella stessa cartella:

    == estrazione ==
• kali-linux.part01.rar
  ✓ estratto (integrato, password trovata)

    Per ogni archivio compare il nome e l'esito: integrato vuol dire che hoster ha fatto da solo, esterno (rar) che si è fatto aiutare da un programma installato (capitolo 6.6).

    !
    Attenzione. se nella cartella c'è già un file con lo stesso nome di uno contenuto nell'archivio, viene sostituito.

    6.2 · Estrarre una cartella già scaricata

    $ ./hoster --extract-only downloads -p LAPASSWORD

    Non scarica niente e non ha bisogno di account né di links: estrae gli archivi di downloads ed esce. Valgono anche --pwfile e --cleanup.

    6.3 · Archivi in più parti

    Un archivio grande è spesso diviso in parti: nome.part01.rar, nome.part02.rar… hoster riconosce il gruppo e lo estrae una volta sola, partendo dalla prima parte. Servono tutte le parti nella stessa cartella: se ne manca una, l'estrazione di quel gruppo fallisce (le altre proseguono).

    6.4 · Password

    Per ogni archivio hoster prova, in quest'ordine:

    1. Nessuna password (molti archivi non ne hanno).
    2. La password data con -p, se c'è.
    3. Le password del file passwords.txt, una per riga, dall'alto in basso (le righe vuote e quelle con # vengono saltate). Il file è facoltativo; --pwfile ne indica un altro.

    Il messaggio finale dice se è servita una password (password trovata) ma non quale, perché non resti scritta sullo schermo.

    +
    Consiglio. se scarichi spesso archivi con le stesse password, scrivile in passwords.txt: non dovrai più indicarle con -p. Come account, anche questo file resta fuori dal repository.

    6.5 · Eliminare gli archivi dopo l'estrazione

    Con --cleanup, dopo un'estrazione riuscita hoster cancella tutte le parti di quel gruppo (compresi i file di recupero .rev) e lo segnala con · archivi del set rimossi. Se l'estrazione fallisce, non cancella niente.

    6.6 · Quando serve rar

    hoster estrae RAR e ZIP da solo, senza programmi esterni. In alcuni casi rari non basta: archivi RAR di formati particolari, ZIP protetti da password, parti danneggiate da riparare con i file .rev. Allora, se sul computer sono installati rar, unrar o 7z, hoster li usa automaticamente e il messaggio dice esterno (rar) (o il nome del programma usato). Su Debian:

    $ sudo apt install 7zip
# oppure
$ sudo apt install unrar
    i
    Nota. hoster non ripara da solo le parti danneggiate. Se un'estrazione fallisce per una parte rovinata e ci sono i file .rev, si può riparare a mano con rar rc, oppure riscaricare quella parte.
    Capitolo 7

    Certificati di sicurezza

    7.1 · Perché compare una nota sui certificati

    Ogni collegamento sicuro (https) si basa su un certificato che il sito presenta per dimostrare chi è. Alcuni server da cui partono i download (per esempio quelli di terabytez) presentano un certificato incompleto: i browser lo accettano lo stesso, i programmi più severi no. hoster se ne accorge e, solo per quel server, prosegue senza quella verifica, avvisando con una riga:

    nota: fs12.terabytez.org:183 ha una catena di certificati incompleta — verifica TLS saltata per questo host

    Tutti gli altri siti restano verificati, e un certificato scaduto o intestato a un altro sito viene comunque rifiutato. Non devi fare niente.

    7.2 · Forzare con -k

    L'opzione -k (o --insecure) salta la verifica per tutti i siti.

    !
    Attenzione. di norma -k non serve: tienila per casi eccezionali e sapendo che toglie una protezione a tutti i collegamenti, compreso quello in cui viaggiano utente e password.
    Capitolo 8

    Siti supportati

    8.1 · L'elenco

    Molti siti di file hosting usano lo stesso programma lato server, XFileSharing: per questo un solo meccanismo li copre quasi tutti. Per usarne uno basta aggiungere la sua riga nel file account.

    8.2 · Provare un sito nuovo

    1. Aggiungi la riga del sito in account e un suo link in links.
    2. Prova senza scaricare: ./hoster --dry-run. Se compare ✓, il sito funziona: puoi scaricare normalmente.
    3. Se compare ✗, rilancia con ./hoster --dry-run --debug dbg: hoster salva nella cartella dbg le pagine che ha ricevuto a ogni passo. Con quelle pagine il programma si può adattare al sito (lo spiega il Manuale Tecnico).
    !
    Attenzione. le pagine salvate da --debug sono quelle che vedi da utente collegato: possono contenere il tuo nome utente, la tua email o dati del tuo account. Non pubblicarle senza averle guardate.
    Capitolo 9

    Recupero su un nuovo dispositivo

    9.1 · Cosa è salvato e dove

    Se il tablet o il computer si guasta, tutto si rimette in piedi da zero in pochi minuti.

    9.2 · Ripartire da zero

    1. Scarica il progetto: git clone https://github.com/nic-fio/HOSTER.git, poi cd HOSTER.
    2. Ricrea i file personali: cp account.example account, scrivi i tuoi dati (per esempio con nano account) e proteggilo con chmod 600 account. Allo stesso modo links e, se serve, passwords.txt.
    3. Verifica con ./hoster --dry-run. Fatto: il programma è già nel repository.
    $ git clone https://github.com/nic-fio/HOSTER.git
$ cd HOSTER
$ cp account.example account
$ nano account
$ chmod 600 account
$ ./hoster --dry-run

    Se vuoi anche poter modificare e ricostruire hoster, prepara la macchina (installa Go e il resto, chiede sudo) e controlla che tutto funzioni:

    $ tools/setup-dev.sh --install
$ make
$ make test

    9.3 · Un backup che non dipende da GitHub

    tools/backup.sh salva l'intero progetto, con tutta la storia, in un solo file che si ripristina anche senza rete:

    $ tools/backup.sh /media/chiavetta
$ git clone /media/chiavetta/hoster-2026-09-24.bundle HOSTER

    Il nome del file contiene la data del backup. Con --personal salva accanto anche un archivio con account, links e passwords.txt:

    $ tools/backup.sh --personal /media/chiavetta
    !
    Attenzione. l'archivio dei file personali contiene le password in chiaro. Tienilo solo su supporti tuoi (una chiavetta, un disco esterno) e mai su servizi pubblici. Un'alternativa comoda è tenere le credenziali dei siti nel tuo gestore di password.
    Capitolo 10

    Riferimento delle opzioni

    Tutte le opzioni, con il valore usato se non le indichi. Si possono scrivere con uno o due trattini: -dry-run e --dry-run sono la stessa cosa. Le opzioni si possono combinare liberamente: ./hoster -j 3 --rate 5M -e -p PW.

    10.1 · Download

    -i FILE
    File con i link da scaricare, uno per riga. Normale: links. Vedi Il file links.
    -a FILE
    File degli account, dominio:utente:password. Normale: account. Vedi Il file account.
    -d DIR
    Cartella in cui salvare i file (creata se non c'è). Normale: downloads.
    -s N
    Connessioni per file. Normale: 1. Vedi Connessioni per file.
    -j N
    File scaricati insieme, e grandezza dei gruppi di link. Normale: 5. Vedi Quanti file insieme.
    -c
    Riprende i download interrotti da dove si erano fermati. Riscarica però anche i file già completi: vedi Interruzioni e ripresa.
    --rate SIZE
    Limite di banda complessivo, per esempio 2M. Normale: 0, nessun limite. Vedi Limitare la banda.
    --timeout SEC
    Secondi di attesa massima per il collegamento e la prima risposta del server durante un download. Normale: 60.
    --retries N
    Nuovi tentativi per ciascun download dopo il primo. Normale: 5.
    --retry-wait SEC
    Secondi di attesa tra un tentativo e il successivo. Normale: 2.
    -U UA
    Come hoster si presenta ai siti (lo User-Agent), per login e download. Normale: quello di Firefox 128 su Linux. Da cambiare solo se un sito lo richiede.
    -k, --insecure
    Salta la verifica dei certificati di sicurezza per tutti i siti. Di norma non serve: vedi Certificati di sicurezza.

    10.2 · Estrazione

    -e, --extract
    Finiti i download, estrae gli archivi RAR e ZIP della cartella dei download.
    --extract-only DIR
    Estrae soltanto gli archivi di DIR ed esce, senza scaricare.
    -p PASS
    Password degli archivi. Vedi Password.
    --pwfile FILE
    File di password da provare, una per riga. Normale: passwords.txt (se non esiste, viene ignorato).
    --cleanup
    Dopo un'estrazione riuscita cancella tutte le parti dell'archivio.

    10.3 · Diagnostica

    --dry-run
    Fa il login e ricava i link diretti, stampandoli, senza scaricare. Vedi Prova senza scaricare.
    --debug DIR
    Salva in DIR le pagine ricevute a ogni passo di login e ricerca del link diretto. Vedi Provare un sito nuovo.
    -v, --verbose
    Mostra anche il link diretto trovato per ogni file (righe con →).
    -qe
    Uscita ridotta: niente barre né messaggi per i singoli file. Restano gli errori che fermano il programma, il conteggio finale scaricati/falliti e i messaggi dell'estrazione.
    -qa
    Come -qe, senza nemmeno il conteggio finale. Gli errori che fermano il programma e i messaggi dell'estrazione compaiono comunque.
    -h, --help
    Mostra la guida integrata.

    10.6 · Esempi pronti

    # scarica i link di 'links' in ./downloads con gli account di 'account'
$ ./hoster

# usa una lista e una cartella di destinazione diverse
$ ./hoster -i kali.txt -d /media/iso

# ricava i link diretti senza scaricare (verifica)
$ ./hoster --dry-run

# scarica e poi estrae gli archivi con la password indicata
$ ./hoster -e -p LAPASSWORD

# estrae una cartella già scaricata
$ ./hoster --extract-only downloads -p PW

# riprende dopo un'interruzione, con meno file insieme e banda limitata
$ ./hoster -c -j 2 --rate 3M

    11.5 · Altre situazioni

    I download sono lenti
    Controlla di non aver dato --rate. Alcuni siti limitano la velocità per singolo file: più file insieme (-j) aiutano; se il sito lo permette, anche -s.
    Non vedo le barre, solo righe di testo
    Succede quando l'uscita non va su un terminale (per esempio se la mandi in un file): è voluto, e le righe di testo sono più adatte a un file di registro. Controlla anche di non aver dato -qe o -qa.
    Voglio l'uscita senza colori
    Imposta la variabile NO_COLOR: NO_COLOR=1 ./hoster.
    Un file già scaricato viene scaricato di nuovo
    Succede con -c (capitolo 5.3), oppure per i link con un codice al posto del nome (capitolo 11.6). Togli dalla lista i file già completi.
    Lo uso in uno script
    Attenzione: se qualche download fallisce, hoster termina comunque con stato 0 («riuscito»). Per accorgersene bisogna leggere la riga finale scaricati: N falliti: M. Vedi Stati di uscita.

    11.6 · Limiti noti

    Comportamenti conosciuti della versione 1.0, da tenere presenti:

    • Con -c anche i file già completi vengono riscaricati. Prima di rilanciare, togli dalla lista i file finiti.
    • I file con un codice al posto del nome (come https://filestore.me/nhail4vmw015) non vengono riconosciuti come già scaricati: a ogni avvio vengono scaricati di nuovo.
    • Lo stato di uscita è 0 anche se qualche download fallisce: il numero dei falliti è solo nella riga finale.
    • Raramente, se due link diretti scadono nello stesso momento, hoster rifà il login sul sito due volte. Non ha conseguenze sui download.
    Capitolo 12

    Glossario

    12.1 · Termini

    Archivio in parti
    Un archivio diviso in più file (part01, part02…) da estrarre insieme. Vedi Cap. 6.
    Certificato
    Il documento digitale con cui un sito https dimostra la propria identità. Vedi Cap. 7.
    Dry run (prova)
    Un giro di prova: login e ricerca dei link diretti, senza scaricare. Vedi Cap. 4.
    File .rev
    File di recupero di un archivio RAR: permettono di ricostruire una parte danneggiata o mancante.
    File hosting
    Sito dove si caricano file per farli scaricare ad altri, con un link per ogni file.
    Gruppo
    I link che hoster lavora insieme: tanti quanti indicati con -j (normalmente 5). Vedi Cap. 5.
    Link diretto
    L'indirizzo da cui parte davvero il file, diverso dalla pagina del file. Dura poco.
    Premium
    Account a pagamento: download senza attese né captcha, spesso a velocità piena.
    Release
    Una versione pubblicata del programma, con il file pronto da scaricare.
    Repository
    La raccolta pubblica su GitHub con il programma, il codice, i manuali e la loro storia. Si copia con git clone.
    User-Agent
    Il modo in cui un programma si presenta ai siti; hoster si presenta come Firefox. Vedi -U.
    XFileSharing
    Il programma usato da molti siti di file hosting: per questo si comportano quasi allo stesso modo.
